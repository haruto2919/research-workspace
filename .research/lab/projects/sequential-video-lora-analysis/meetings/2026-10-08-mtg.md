## やったこと

- 画像事前学習済みViTを固定し、時間順に入力される動画に対してAttention Q/VのLoRAをMoCoで自己教師あり学習する実験を実装・実行した。
- 学習済みLoRAの有用性を、ActivityNet segmentを単位とするLinear ProbeでBase ViTと比較する計画を進めた。ただし、MoCo学習中の挙動に未解決の問題があり、Linear Probeによる比較結果の解釈段階にはまだ到達していない。
- 現行の比較で検証できる主張を、「MoCoで学習したLoRAを追加すると、ActivityNetの動作分類で線形分類に利用できる特徴が得られるか」に限定した。現行の特徴抽出は各frameのCLS特徴をmasked meanするため、Linear Probeの改善だけでは時間順序や動きを直接理解したとは結論できないことを確認した。
- Comet上の実験ログを確認対象として共有した。今回のMTGでは、ログの具体的な数値を成功結果として確定していない。

## 実験設定の共有

### MoCo学習

| 項目 | 現在の設定 |
|---|---|
| データ | ActivityNet v1.3 training、10,024動画を1回ずつ処理 |
| Encoder | `google/vit-base-patch16-224`、画像事前学習済み、Base固定 |
| 動画入力 | 16 frames/chunk、1動画を最後まで処理して次の動画へ進む `strict_single` |
| 特徴量 | frameごとのCLS `[768]` → valid frameのmasked mean → chunk `[768]` |
| 学習対象 | Query側ViTのQ/V LoRA（rank 8、alpha 8）とQuery Projector |
| Key側 | Key LoRAとKey ProjectorをEMAで追従 |
| Positive | 同じchunkにRGB→GBRのチャンネル入替と左右反転を適用したView |
| Negative | FIFO Queue内の過去Key全件。同じ動画の過去chunkも含む |
| MoCo設定 | Projection 128、Queue 4,096、EMA momentum 0.999、temperature 0.07 |
| Optimizer | AdamW、learning rate 0.001、weight decay 0 |

### ActivityNet segment Linear Probe

- 動画全体ではなく、ActivityNet annotationの動作区間を1サンプルとする。
- 有効フレームのtimestampがsegment内にすべて入るchunkだけを採用し、対応chunkがないsegmentは除外件数を記録する。
- Base ViTと最終Query LoRA付きViTで、manifest、segment ID、分割、特徴定義を一致させる。
- 768次元特徴を固定し、200クラスの線形分類器だけを学習する。Cross Entropy、AdamW（LR 0.001、weight decay 0.0001）、batch size 256、100 epoch、seed 0/1/2を予定している。
- 主指標は最終epochのvalidation Top-1 Accuracyとする。

## 話したこと

### 現在の問題：MoCo学習の挙動

- MoCoのlossに大きな振動が見られ、Query LoRAの勾配も初期には小さいながら継続していたものが途中で急に大きくなっている。
- これはLinear Probeの比較へ進む前に原因を切り分けるべき問題であり、現時点では実装上の問題か、データ・入力条件・MoCo設定によるものかを判断できていない。
- 確認対象として、strideをloader側で変更可能にすること、オンライン入力によるデータ影響を調べること、MoCoに適したデータセットで期待される学習曲線を確認することが挙がった。
- 参照実装のGitHubリポジトリをそのまま動かし、基準となるlossや各種ログを得てから現在の環境へ移植する案も挙がった。

### 小さなステップでのコンポーネント検証

- 現在はSequential Loader、ViT、LoRA、MoCo、Linear Probeを一度に組み込んでいるため、どの部品が原因か分かりにくい状態になっているという指摘があった。
- まずSequential Loaderや本研究の統合経路から切り離し、LoRA単体で通常の学習を行い、LoRAの付け方・対象module・forward・勾配・parameter更新が意図どおりかを確認する。
- 次に、Sequential Loaderとは無関係な標準的な設定でMoCo単体を動かし、MoCoとして正しい挙動をしているかを確認する。
- 各ツールを単体で理解・検証した後に、Sequential Loaderと統合した実験へ戻る方針とした。

### LoRA実装とライブラリ

- 現在のLoRA実装は、研究上の目的や公式性を十分に確認しないまま、検索で見つけた特定リポジトリの実装を取り込んだ経緯がある。
- そのリポジトリは公式LoRAライブラリではなく、特定研究・特定ハードウェア向けの参考実装である可能性が高い。今後の基盤としてそのまま使うのは避ける方針とした。
- Hugging Face PEFTなど、信頼性と利用方法を説明できる既存ライブラリが現在のViTに適用可能か調べる。また、研究室内で使われている簡潔な実装方法について髙間さんに確認する。
- どのライブラリを採用するかは、単体検証で挙動を説明できることと、現在のモデルへの適用可能性を確認してから決定する。

### 研究室紹介・オンライン学習の説明

- 研究室紹介では、いきなり自分の実装やMoCoの詳細に入らず、まず「通常のAI学習はオフライン学習が一般的である」ことを説明する。
- 動画をオンライン・逐次的に学習する難しさとして、データを自由にshuffleできず統計的に偏った順序で処理する必要があること、長い動画をそのままメモリに載せにくいこと、近接frameの冗長性が高く学習上の扱いが難しいことを示す。
- そのうえで、なぜオンライン学習が一般的でないのか、どのような研究課題が残っているのかを説明し、最後に自分の研究へつなげる構成とする。
- スライドや実際のartifactを使い、専門用語を増やしすぎずに説明できる具体例をもう一つ検討する。

### その他

- 研究室内の係の見直しについて、環境整備係から別の係へ移る可能性が話題になった。具体的な担当と指示は未確定である。

## 決定事項・方針

- MoCoのloss振動とQuery LoRA勾配の急増を確認・切り分けるまで、Linear Probeの結果を研究上の結論として扱わない。
- LoRA単体、MoCo単体、Sequential Loader単体の順に、各コンポーネントの使い方と期待挙動を確認してから統合する。
- 現在の出所と挙動を十分に説明できないLoRA実装を基盤として使い続けず、信頼できる既存ライブラリまたは研究室内で実績のある簡潔な実装を調査する。
- 研究室紹介は、オフライン学習を前提とした一般的なAIから始め、オンライン学習が難しい理由と研究上の必要性を説明してから、自分の研究内容へ接続する。

## 未決定事項・注意点

- loss振動・勾配急増の原因が、LoRA実装、MoCo実装、入力stride、positive/negative設計、データ順序のどこにあるか。
- LoRAに採用するライブラリと、現在のViT Q/Vへの具体的な適用方法。
- 参照用MoCo実装・データセットをどれにするか、および期待する学習曲線の基準。
- 現行の統合経路でLinear Probeを再開するための検証完了条件。
- 研究室紹介で使う追加の具体例とartifact。
