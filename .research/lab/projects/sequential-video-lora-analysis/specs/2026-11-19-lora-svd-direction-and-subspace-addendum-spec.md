# LoRA の SVD 解析：向きの比べ方と部分空間の比較（追補）

[元の spec](2026-11-18-lora-svd-export-and-viewer-spec.md)（以下「元 spec」）への追補。元 spec のうち、ここに書いていないことはそのまま有効とする。

## 1. 目的

LoRA・SVD 解析の文献調査をもとにビューアを見直したところ、次のことが分かった。改善案デモで、5 つの変更を実データで試した。

- 「向きのずれ」が大きく出すぎている。
  - 原因：W₀ の上位の特異値は、隣との差が 1% 未満の組が多い。そのため、1 本ずつの対応付けでは、部分空間の中での回転も「ずれ」に数えてしまう。
  - 大きさ：デモで比べると、部分空間で測った値の 2.6〜5.6 倍だった（24 行列の中央値、run ごと）。
- 学習後の向きを、W₀ の上位 16 本としか比べていない。
- 「有効ランク」の定義が画面に書かれていない。
- 次の 2 つを見る手段がない。
  - run どうしで、ΔW の向きが同じかどうか。
  - 学習の途中で、向きがいつ決まるか。

この追補では、デモの修正 1〜3 と追加 4〜5 を、書き出しスクリプトとビューアに入れる。**修正 2 は、今のヒートマップの形を保つ**（ユーザーの指示、2026-11-19）。

## 2. 前提（2026-11-19 に確認）

- 研究コード：`feature-lora-svd@a549e34`（clean）。
- 最新の書き出し：`2026-11-19_04-19-36`（schema `lora_svd/1`、9 run・27 checkpoint）。
- 書き出しは CPU で約 3 分半かかる。
- 今の実装：
  - `top16_cos_mean` = (1/16) Σᵢ maxⱼ M[i, j]（元 spec 5.3）。M = |U₀ᵀ U′|（16×16）。
  - ビューアの「向きのずれ」は 1 − `top16_cos_mean`。
  - `svd_vectors.csv` には、ΔW の U と V の上位 r 本（r はグループの LoRA の rank。今は 8）が、全 checkpoint 分ある。Full FT も r 本。
- 9 run はすべて `seed: 0`。LoRA の A は、同じ初期値から始まっていると考えられる。

## 3. Decision Contract

### 採用

| # | 内容 | 書き出しの変更 |
|---|---|---|
| 1 | 「向きのずれ」を、1 本ずつの対応ではなく、上位 16 本が張る部分空間で測る。あわせて主角（principal angles）の cos を 16 個出す。 | あり |
| 2 | 今のヒートマップ（縦 W₀ の上位 16 本、横 W₀+ΔW の上位 16 本、|cos|）を保ったまま、下に 1 行だけ足す。足す行は「W₀ の 17〜768 番の中で最も近いもの」。列ごとの最大が小さい列（新しい向き）に印を付ける。 | あり |
| 3 | 有効ランクの式を画面に書く。比べるために stable rank も出す。 | なし |
| 4 | run どうし（または step どうし）で、ΔW の上位 r 本の部分空間の重なり φ(i, j) を見る画面を足す。 | なし |
| 5 | 「学習の推移」に、特異値 σ₁〜σᵣ、有効ランク、最後の step との向きの重なりを足す。 | なし |

### 対象外

- 新しい学習や評価の run。
- 「新しい向き」のしきい値を、統計的に決めること（今回はビューアで動かせる仮の値にとどめる）。
- run どうしの差が「順番に読む学習」のせいかどうかの判断（4 節の「主張しないこと」）。
- W₀ や W₀+ΔW の特異ベクトルそのものを保存すること（元 spec のとおり、保存しない）。
- 古い形式（`lora_svd/1`）の書き出しを、新しいビューアで読むこと（3.4 を参照）。

### 棄却した案

- **修正 2 を棒グラフにする案**（デモの形）：ユーザーの指示で、今のヒートマップの形を保つ。
- **1 本ずつの「向きのずれ」を残して並べる案**：同じことを 2 通りに出すと、どちらを見ればよいか分からなくなる。根拠はデモと 1 節に残っている。

## 3.1 修正 1：部分空間での向きのずれ

- U₀ = W₀ の上位 t 本の左特異ベクトル、U′ = W₀+ΔW の上位 t 本の左特異ベクトル（t = min(16, 次元)）。
- **重なり**：φ = ‖U₀ᵀ U′‖²_F ÷ t（0〜1。1 なら同じ部分空間）。
- **主角の cos**：U₀ᵀ U′ の特異値を大きい順に t 個（0〜1 に収める）。
- **書き出し**：`svd_summary.csv` の列を変える。
  - 削除：`top16_cos_mean`
  - 追加：`top16_span_overlap`（= φ）、`pa_cos_1 … pa_cos_16`（主角の cos）
  - `pretrained` の行は空欄。
- **ビューア**
  - 全体マップの「向きのずれ」を 1 − φ にする。説明文の定義も書き換える。
  - 「特異値分解の行列」の「そのまま」表示で、ヒートマップの下に主角の cos を 16 本の棒で出す。

## 3.2 修正 2：ヒートマップに「17〜768 番」の行を足す

- **ヒートマップの形は今のまま**：縦 = W₀ の 1〜16 番、横 = W₀+ΔW の 1〜16 番、色 = |cos|、色の尺度も今のまま。
- **足す行**：16 行目の下に 1 行だけ足し、「W₀ の 17〜768 番」と表示する。
  - 列 j の値：W₀+ΔW の j 番と、W₀ の 17〜d 番（d は次元）との |cos| の最大。
  - ホバーで、それが W₀ の何番かを出す。
  - 16 行との間に少し隙間を空けて、別の行だと分かるようにする。
- **新しい向きの印**
  - 列 j の 17 行すべての最大（= W₀ の全 d 本との最大 |cos|）がしきい値より小さい列に、列の上に印を付ける。
  - しきい値はヒートマップの横のスライダーで動かす（0.2〜0.9、既定 0.5）。
  - 印の数と「しきい値は仮の値」という注記を表示する。
- **書き出し**：`merged_overlap.csv` に列 `w0_index` を足す。
  - 1〜16 行目：`w0_index = i`。
  - 足す行：`i = 17`、`cos` = W₀ の 17〜d 番との最大 |cos|、`w0_index` = その番号（同じ値なら小さい番号）。
  - d ≤ 16 のとき（テストの小さな ViT）は、この行を書かない。

## 3.3 修正 3：有効ランクの定義

- 全体マップの説明と、「特異値スペクトル」の統計に、式を書く。
  - 有効ランク = exp(−Σ pᵢ log pᵢ)、pᵢ = σᵢ² ÷ Σⱼ σⱼ²（今の実装の値のまま）
- 「特異値スペクトル」の統計に、stable rank（Σσᵢ² ÷ σ₁²）を足す。
  - LoRA：rank 個すべての特異値から求めるので正確。
  - Full FT：上位 32 個しかないので、出さない。
- 値の計算は変えない。

## 3.4 形式の版を上げる

- schema を `lora_svd/2` にする。`manifest.json` の `schema` も同じ。
- ビューアは `lora_svd/2` だけを読む。
  - `lora_svd/1` の書き出しを開いたときは、「古い形式です。書き出し直してください」と出し、何も表示しない。
  - ファイル選択で `manifest.json` がない場合は、列名で判断する（`top16_span_overlap` がなければ、同じ案内を出す）。
- 今ある書き出し（`lora_svd/1`）は消さずに残す。

## 3.5 追加 4：run どうしの部分空間

- **新しい画面**「run どうしの比較」を、「特異値分解の行列」の後ろに置く。必要なのは `svd_vectors.csv` だけで、書き出しは変えない。
- **選ぶもの**
  - A と B のそれぞれで、run と step を選ぶ。同じ run の別の step も選べる。既定は、今のグループの LoRA の最後の step と、別グループの LoRA の最後の step。
  - 層とモジュールは、ほかの画面と共通。
  - U（出力側）か V（入力側）か。既定は U。
- **表示**
  - **ヒートマップ**：φ(i, j) = ‖Uᵢᵀ U′ⱼ‖²_F ÷ min(i, j)（i, j = 1〜r）。r は A と B で少ない方の本数。
  - **全組の表**：登録した全 run の最後の step どうしの φ(r, r) を、24 行列の中央値で表にする。マスを押すと、その組を上のヒートマップで見る。
- **注記（画面に出す）**
  - 無関係な向きどうしの目安：φ(r, r) ≈ r ÷ d（今は 8 ÷ 768 ≈ 0.010）。
  - V について：全 run が同じ seed なので、LoRA どうしの V は A の初期値を共有していて、高めに出る。
- **計算はビューアで行う**：全組の表は 36 組 × 24 行列。

## 3.6 追加 5：学習の推移

「学習の推移」の切り替えに、次の 3 つを足す。今の 3 つ（‖ΔW‖_F、W₀ 比、直前からの変化）はそのまま残す。

| 切り替え | 線 | 横軸 |
|---|---|---|
| 特異値 | 選んだ層・モジュールの σ₁〜σᵣ（r 本。上位ほど濃い同じ色相） | 登録した checkpoint の step |
| 有効ランク | 今の推移と同じく 12 層の線（選んだ層を強調） | 同上 |
| 最後との向き | 各 step と、その run の最後の step の、U の φ(r, r)。12 層の線 | 同上 |

- step 0（学習前、ΔW = 0）は、特異値の線では 0 とする。有効ランクと向きでは定義できないので、描かない。
- 値は `svd_summary.csv` と `svd_vectors.csv` から求める。書き出しは変えない。

## 4. 主張しないこと

- 「新しい向き」の本数は、しきい値（仮）しだいで変わる。判断の基準にしない。
- run どうしの φ が高くても、その理由（順番に読む学習、学習の長さ、seed、A の初期値）は、この画面だけでは切り分けられない。
- 元 spec と同じく、特異値の大きさから、LoRA が静的・動的のどちらの情報を持つかは言わない。
