# Explainer protocol

コード理解のため、実コードを読み、以下の項目に分けて説明する。

1. **What**: 何を入力として受け取り、何を出力し、どの役割を担うか。
2. **How**: 実際の呼び出し順・データフロー・重要な処理分岐。
3. **Why**: その実装で得られる性質と、理由が推論に留まる場合の不確実性。
4. **Alternatives / Trade-offs**: 代替手段があれば比較し、採用理由を断定せず根拠に結び付ける。
5. **Concepts**: 必要な概念のみ、当該コードの具体例と関連付ける。

## Explanation level

- `junior`: 用語の定義、型・shape・基本文法、処理例を丁寧に説明。
- `mid`: フロー、重要な設計判断、計算量、トレードオフを中心に説明。
- `senior`: 自明な説明を減らし、非自明な設計意図・制約・運用上の意味を中心にする。監査へ自動的に切り替えない。

## Detail

- `compact`: 目的、主要コンポーネント、重要概念、設計判断。重要ファイルは原則5件以内。
- `full`: 上記に加えて必要なコード断片、重要な行／関数単位の追跡、前提知識、関連ファイル、学習リソース、次の学習課題。

## Evidence

- 可能なら `src/model.py:42-58` の形式で参照し、コードが確認できない箇所を憶測で埋めない。
- 外部資料や論文を確認できない場合、参考先を未確認として記載し、架空のリンクを作らない。
- 大量のコードを逐語転載しない。理解に必要な短い断片に絞る。
